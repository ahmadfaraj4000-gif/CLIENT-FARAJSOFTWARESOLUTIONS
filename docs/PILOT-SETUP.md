# Shift Planner managed pilot

## What is implemented

The client portal contains Overview, Schedule, Time Clock, Timesheets, Employees, and Settings. Each business has one location, an owner, and optional managers. NFC and QR codes open an employee-specific experience after phone enrollment; they do not identify a person themselves. Car Craft's existing Convex application and records are untouched.

Manager access uses Supabase Auth. Workforce mutations use permission-checked database functions; workforce tables have RLS enabled and direct browser reads/writes are revoked. Device and enrollment credentials live in a private schema. Employee clock calls go through the `time-clock` Edge Function, which calls the service-role-only `rt_clock` database function. The browser receives only the enrolled employee's clock state and published upcoming shifts, never wages or other employee records.

## Deployment order

1. Back up the target Supabase database. Review existing `subscriptions`, `profiles`, `support_messages`, and legacy planner tables against the additive bootstrap migration. No existing schedule is deleted or overwritten.
2. Link the intended Supabase project using the CLI, inspect the pending migration list, and apply migrations in filename order with `supabase db push`. The new migrations bootstrap missing legacy portal tables; they do not replace the Pricing Assistant tables. For a new installation also apply `faraj-admin-portal/sql/05_pricing_assistant_tables.sql`. Migration 005 preserves existing trial entitlements but rejects new self-service Shift Planner trials.
3. Set the Edge Function origin allowlist to the exact HTTPS client portal origin. Example: `supabase secrets set CLOCK_ALLOWED_ORIGINS=https://login.reimagebstech.com`. Add localhost origins only to a development project. Supabase supplies `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` to its hosted runtime.
4. Deploy with `supabase functions deploy time-clock`. `supabase/config.toml` disables gateway JWT enforcement only for this employee endpoint because it validates its own enrolled-device credentials. Manager RPCs still require Supabase Auth.
5. Build/deploy the client and admin portals to their existing hosts. The GitHub Pages workflow still uses the existing internal directory. Deploy the root HTML, `styles.css`, `brand-config.js`, and `shared/` assets together for the public site. Do not publish `.env*`, `tests/`, `node_modules/`, or Supabase credentials.
6. Run the two-business and phone acceptance checks below on staging before granting the first real business access. Production deployment and physical NFC tests are not completed by the local automated test suite.

There is no new billing integration. In the admin portal, find the owner's registered account, select Shift Planner, and grant access. Owners create their business in the client portal. Managers register their own portal accounts and are added by email in business Settings. Existing platform admin authorization remains `farajsoftwaresolutions@gmail.com` unless migrated separately.

## Business onboarding

- Confirm business name, IANA timezone, workweek start, weekly overtime threshold/multiplier, break policy, labor budget/percentage, opening hours, and minimum coverage. Defaults: USD; America/New_York; Monday; 40 hours and 1.5×; unpaid recorded breaks; location enforcement off.
- Timezone/workweek changes are blocked once schedules or punches exist, to protect historical boundaries. Cost-setting changes invalidate previous approvals for review. Future break policy changes are recorded on each new break, preserving existing break treatment.
- Add employees, roles, current wages, weekly hour caps, and unavailable days. Rate changes apply from the time saved. Use the historical-rate form with an effective date and reason to enter verified historical wages before reviewing old records.
- Create a draft, add/edit multiple dated shifts per person, or review a generated proposal. The generator respects availability and weekly limits, balances assignments, and uses wage as a tie-breaker. It flags coverage/budget tradeoffs instead of publishing automatically. Publish explicitly to show employees their schedules.
- From Time Clock, copy the NFC URL into an NFC-writing app as an ordinary URL record. Download and print the matching QR code. Each employee gets a one-use, 24-hour enrollment code. Codes are shown to the manager for private sharing; they are not emailed automatically.
- Employees use their own phone and browser. Sessions expire after 180 days. Enrollment of a replacement phone revokes older phone sessions. Deactivation or Revoke phones revokes sessions and outstanding codes. Replacing the workplace link requires rewriting tags/reprinting QR codes.
- For location enforcement, configure the workplace coordinates, allowed radius, and maximum accepted GPS uncertainty in meters. The whole uncertainty radius must fit inside the workplace radius. Checks occur at punch time only. A copied static tag URL alone does not prove physical presence; geolocation is an additional check, not a tamper-proof hardware attestation.

## Timesheets and calculation behavior

Original clock events are preserved. Corrections store the original reference, replacement/void, reason, manager identity, and timestamp. A correction must leave a valid chronological event sequence. Add missing events in chronological order; correct conflicting records first. Manager-entered history uses the current paid-break setting, so verify the applicable break policy before entering old break records.

Times are stored as UTC instants and displayed in the business timezone. Week boundaries and elapsed durations handle DST. When entering a repeated clock hour, the manager can explicitly choose its first or second occurrence. Missing clock-out/open shifts remain provisional; shifts open over 16 hours are flagged. Employee clock actions require an online server confirmation. Retry the same unconfirmed action rather than treating a network error as success.

Scheduled costs use the published shift and its explicit planned break. Zero planned break minutes means the full scheduled duration is paid; an unpaid planned break deducts only its configured interval from the estimate. Planned breaks never create or alter actual punches. Actual hours deduct only recorded unpaid breaks. Wages use effective rate history. Weekly overtime is applied chronologically using the configured threshold/multiplier, with final totals rounded to cents. These are gross-wage estimates, not a tax calculation or payroll payment service. Missing historical rates mark costs incomplete. Actual labor percentages, when compared with projected revenue, remain estimates rather than realized profit figures.

Only completed workweeks with resolved attendance can be approved. Corrections and historical wage changes invalidate affected employee approvals; business cost-setting changes invalidate business approvals. CSV reports distinguish provisional, incomplete, unapproved, and approved records. CSV text is escaped against spreadsheet formula execution. Printable reports use the browser's Print/Save as PDF feature.

Expired pilot access blocks manager dashboards, reports, editing, enrollment, and new clock-ins on the server. Cached workforce data is cleared when refresh is denied. Business names and access status remain visible through bootstrap so managers can identify the locked business. Already-enrolled employees can finish a break or clock out from an open shift. If an employee was deactivated or lost their phone, an active manager must record the correction.

## Schedule and attendance reconciliation

Migration 006 adds planned breaks, configurable alert tolerance (default 5 minutes), matching window (default 240 minutes), immutable published shift snapshots, and append-only attendance reviews. Backfilled snapshots capture the published plan present at migration time; unavailable earlier publication versions cannot be reconstructed. A draft remains editable, while employees continue to see the last published version until the manager publishes changes. Publishing a different draft for the same workweek replaces its future baseline; started plans remain historical evidence. Previously published schedules cannot be deleted. Started published shifts, including those with an early clock-in, are preserved; use attendance corrections for actual-time errors.

Timesheets → Schedule vs attendance compares the published baseline with recorded sessions. Automatic matching uses stable employee IDs and a start within the configured window or inside the shift. Planned breaks also reduce coverage estimates whether paid or unpaid. Break duration differences are flagged even when paid hours match. Multiple candidates or competing sessions require manager assignment; multiple sessions may be explicitly assigned to one shift. Unscheduled attendance remains in actual costs. Review can acknowledge a variance, assign a shift, or confirm unscheduled work with a reason. Review never changes a punch. Changed evidence reopens the exception and reviews reset that employee's timesheet approvals. The review queue assists approval; managers remain responsible for checking the full timesheet.

Alert tolerance suppresses small differences only. Every recorded second still contributes to hours and costs; there is no rounding to planned start/end, automatic lunch deduction, or automatic clock-out. Missing clock-ins are flagged after the tolerance; open scheduled shifts past their end are flagged for a missing clock-out. An unmatched open shift is flagged after 16 hours. Forecast labor combines actual paid time so far with remaining paid published shifts, applies overtime chronologically, and removes remaining time from shifts already clocked out. It does not invent an end for unscheduled open work. Missing attendance and uncertain matches label the forecast uncertain. Forecast is an estimate, never an approved timesheet.

## Pricing Assistant integration

Cost Structure → Import from Shift Planner opens a business/week/source picker. Choose published scheduled labor, approved actual labor, or a forecast estimate; preview totals and explicitly replace the labor tiers. The `rt_pricing_labor` RPC requires business membership, the owner's active `shift_planner` entitlement, and the importing user's active `pricing_assistant_pro` entitlement on every preview and confirmation. Managers inherit business planner access but need their own Pricing Assistant entitlement. Expiration of either product blocks import; there is no fallback to legacy saved JSON.

Approved actual imports require a completed workweek with all worked employee timesheets approved. Missing wage history blocks imports. Each imported employee tier uses paid hours and an effective hourly cost that preserves gross wages including historical rate changes and overtime. Unscheduled employees with zero paid hours are omitted; maximum available hours are never substituted. Source business/week/basis is saved with the local draft and cost profile, and manual edits are labeled. These are explicit snapshots: import again to refresh assumptions. The confirmation rechecks authorization and refreshes the preview if totals materially changed (over one cent or 0.01 hours).

## Existing schedules

The Schedule tab lists the owner's legacy saves. Confirm the historical workweek date; relative `weekOffset` values are never guessed. The import uses legacy employee IDs, preserves source JSON, imports draft shifts/rate history, and is repeatable without duplication. Conflicting identities, duplicate names under different IDs, and conflicting wage history stop the transaction for review. Do not resolve ambiguity by blindly merging employees. Original legacy schedules remain available for comparison and rollback.

## Pilot acceptance and monitoring

Use synthetic businesses A and B first. Verify both directions of isolation, owner/manager permissions, and no employee access to wages. Complete enrollment, clock-in, unpaid/paid break, clock-out, duplicate retry, revocation, deactivation, and missed-punch correction. Test unavailable/expired codes and expired business access. Publish a shift with a planned break, clock in slightly late and clock out slightly late, then compare exact paid hours with the plan. Test ambiguous matches, confirmed unscheduled work, a reviewed exception reopened by correction, and an early clock-in followed by a rejected plan edit. Verify employee schedules persist while the manager edits a draft. In Pricing Assistant, preview and confirm scheduled/approved-actual/forecast imports, verify weighted costs, and verify both product expirations deny imports. Review an overnight shift, a DST boundary, weekly overtime, historical rates, and a corrected timesheet; compare exports to independently calculated totals.

On a physical iPhone and Android phone, tap the actual programmed tag and scan the printed QR code. Test location allowed/denied, outside radius, poor GPS, browser restart, and lost connection before/after confirmation. Confirm the final server record after each network retry. Mobile browser emulation cannot replace this hardware check.

Monitor Supabase Edge Function errors (`clock_rpc_failure` logs contain error codes, not request tokens), API latency, enrollment throttling reports, and unresolved open shifts during the pilot. The current dashboard loads business history in one request and refreshes every 30 seconds; add paginated reports before scaling beyond small pilot businesses. No employee notifications or continuous location collection are included.

Rollback by restoring the previous frontend while preserving the new attendance tables and original legacy schedules. Do not drop clock records as part of a rollback. If clock writes must stop, disable the tag or revoke device access and reconcile outstanding shifts before switching workflows.
